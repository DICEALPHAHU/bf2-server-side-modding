# BF2 服务端模组 —— 调查结论与工具

关于 **战地2（Battlefield 2）服务端到底能改什么、不能改什么** 的逆向笔记、可用工具和实测证据。
全部在**原版 BF2 1.5.3153** 客户端 + 专用服务端上实测得出，不是转述论坛传说。
凡是流传很广但被实测推翻的说法，证据都附在里面。

> English: [`README.md`](../README.md)

---

## 核心结论

**原版 BF2 服务端无法让客户端显示出"客户端本地地图文件里没有"的建筑。**
运行时不行，加载时不行，通过任何 Python API 都不行。

```
客户端建筑几何体  ←  client.zip\terraindata.raw   (44 MB，烘焙，服务端动不了)
服务端碰撞        ←  server.zip + Python           (服务端说了算)
```

**这是两个独立的东西。** 所以服务端把建筑挪走后会出现"幽灵"：
客户端还在原地画那栋楼，但那里已经没有碰撞了。

---

## 实测证据

全部在原版图 `Dalian_Plant` 上测试，且**客户端与服务端的 `client.zip` 逐字节相同**（MD5 校验通过）。

| # | 实验 | 服务端 | 客户端 |
|---|---|---|---|
| 1 | 运行时 `Object.create woodencrate_4m` | ✅ 数量 `12→13`，返回 `id36117` | ❌ 什么都不显示 |
| 2 | 运行时移动已有物件 | ✅ readback 确认新坐标 | ❌ 模型留在原位 |
| 3 | 运行时删除已有物件 | ✅ 数量下降 | ❌ 照样显示 |
| 4 | 可见性开关（`setActive`/`setIsVisibleRecursive`/`Object.start`/`initGrid`） | ✅ 接受 | ❌ 全部无效 |
| 5 | 改服务端 `StaticObjects.con` 挪建筑位置 | ✅ `spwfind` 报新坐标 | ❌ 仍在旧坐标渲染 |
| 6 | **从服务端 `StaticObjects.con` 删除建筑** | ✅ `907→906` | ❌ **照样显示** |
| 7 | 加载时增加 3 个建筑实例 | ✅ `907→910` | ❌ 不显示 |
| 8 | `DestroyableObject` 类（`c_NIGhostAlways`） | ✅ 创建成功 | ❌ 不显示 |
| 9 | `mountArchive` 注入新物件 | — | 💥 客户端崩（`NetworkManager.cpp:233`） |
| 10 | 地图包里放 Python（8 个位置探针） | ❌ 从未执行 | ❌ 从未执行 |
| 11 | `python/bf2/*` 与 `mods/bf2/python/.../gpm_cq.py` | ✅ **全部加载，`init()` 执行** | ❌ **从未加载** |
| 12 | 客户端联机时是否运行 Python | — | ❌ **不运行** |

**第 11、12 条是决定性的。** 服务端 Python 跑得好好的；而客户端在联机模式下
**从不启动解释器**。所以任何"服务端告诉客户端做某事"的设计，**接收方根本不存在**。

详细分析：[`FINDINGS.zh-CN.md`](FINDINGS.zh-CN.md)

## 真正能用的部分

服务端**确实能**创建、移动、删除物件 —— 只是没法给任何人看。
所以它的实用价值在**地图编辑、坐标采集、调试诊断**。

装上模组可得 **18 条 RCON 命令**：

| 命令 | 用途 |
|---|---|
| `rcon spwpos` | **查自己坐标** —— 直接是 `X / Y / Z` 格式，可以粘进 `.con` |
| `rcon spwfind <模板名>` | **查某物件在世界里的位置** + 离你多远 |
| `rcon spwdump [半径]` | **列出周围的物件模板名** —— 用来查"这栋楼叫什么" |
| `rcon spwtest` | 一键生成测试，带完整过程报告 |
| `rcon spw <模板名> ...` | 在你位置创建物件 |
| `rcon spwstack` / `spwmovetest` / `spwbump` | 搬动已有物件（测碰撞/渲染） |
| `rcon spwmoveback` | 还原上面的搬动 |
| `rcon spwdel <模板名>` | 删除物件 |
| `rcon spwdiag` / `spwlist` / `spwraw` / `spl` / `spwenv` | 诊断用 |

**安装步骤与完整命令参考：[`USAGE.zh-CN.md`](USAGE.zh-CN.md)**

## 那要改建筑该怎么办

要让玩家**看见**变化，只能**改地图包并让玩家下载**：

- `client.zip` 和 `server.zip` **必须同时改**
- 两边要**严格一致**，否则产生"幽灵建筑"（看得见、摸不到）
- 这是标准做法，所有自定义 BF2 地图都是这么做的

BF2 模组也常常**共用原版地图名但内容不同**。那些"神迹服务器"最可能的解释就是：
**客户端一直在用模组的文件**，而不是运行时接收到了什么。

## 踩过的坑（每条都花了真实时间）

| 坑 | 说明 |
|---|---|
| **内嵌 Python 是 2.3.4** | 不支持三元表达式、`sorted()`、`set()`、装饰器、`with`、`except X as e` |
| **`os` 模块被阉割** | 没有 `os.getcwd`/`os.path`/`os.listdir`。只能用 `__file__` 字符串切分 |
| **非 ASCII 会炸** | 源文件必须纯 ASCII。文档字符串里一个中文注释 = SyntaxError |
| **语法错误是静默的** | 一个模块出错会让**整个 `standard_admin` 包**导入失败，**没有任何提示**。所以才需要 `zzdoctor.py` —— 它会逐个 compile 检查并记录原因 |
| **`+modPath` 不存在** | `bf2_w32ded.exe` 里根本没这个字符串 |
| **命令行不解析引号** | 带空格的路径只能靠 `cd` 切到安装根目录 |
| **RCON 密码在 `Admin\default.cfg`** | 不是 `sv.rconPassword`。该文件默认不存在，不建就用不了 RCON |
| **`ctx.player` 只有游戏内 rcon 有** | TCP rcon 和服务端本地控制台没有玩家上下文，涉及坐标的命令会失败 |
| **`sendClientCommand` 是 UI 事件通道** | `command` 是**数字**（如 `100` = TK 惩罚对话框），不是命令字符串。它无法让客户端执行任何东西 |

## 范围与诚实声明

本文档记录的是**一个特定的引擎版本**（BF2 1.5.3153）。
更早的补丁可能行为不同，大型模组也可能改变结论。

**也存在"某个机制是这 12 个实验没能撞到"的可能。**
如果你知道，**非常欢迎提 issue 并附上复现步骤** —— 最好带上"服务端运行时创建的对象
在客户端屏幕上出现"的截图。

本仓库**没有**声称"这个技术从来不存在"。它声称的是：
在原版 1.5 客户端、客户端文件未改动的前提下，服务端无法注入可见几何体 ——
并给出了得出这个结论的全部实验。
